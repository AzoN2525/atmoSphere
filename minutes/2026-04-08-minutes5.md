## Objetivo da Reunião

Dar início ao **desenvolvimento conjunto da API**, bem como definir a abordagem para **simulação de dados ambientais**, incluindo geração de dados históricos e futuros.

---

## Agenda

1. Desenvolvimento da API em conjunto  
2. Definição dos agentes de simulação de dados  
3. Estrutura dos dados e estratégia de geração temporal  

---

## Discussões e Decisões

### 1. Ponto 1: Desenvolvimento da API em conjunto

**Discussão:**  
A equipa trabalhou de forma colaborativa no desenvolvimento inicial da **API**, focando-se na definição da estrutura base do projeto e na implementação dos primeiros componentes.

Foram discutidas abordagens para garantir consistência no código, organização das camadas (controllers, services, repositories) e alinhamento com a arquitetura previamente definida.

Houve também preocupação em garantir que o desenvolvimento segue boas práticas, facilitando a integração futura com o frontend e a documentação da API.

**Decisão:**  
Ficou definido que o desenvolvimento da **API** será feito de forma coordenada entre os membros da equipa, mantendo consistência estrutural e alinhamento com a arquitetura estabelecida.

---

### 2. Ponto 2: Definição dos agentes de simulação de dados

**Discussão:**  
A equipa definiu a necessidade de criar **agentes responsáveis pela geração de dados**, com o objetivo de simular sensores ambientais (ex.: qualidade do ar, ruído, tráfego).

Foi discutido o papel destes agentes como produtores de dados contínuos, permitindo alimentar o sistema mesmo na ausência de dados reais.

**Decisão:**  
Foi acordado que serão implementados **agentes de simulação**, responsáveis por gerar dados de forma automática e contínua, representando diferentes tipos de sensores.

---

### 3. Ponto 3: Estrutura dos dados e estratégia de geração temporal

**Discussão:**  
Foram discutidos os formatos e atributos dos dados gerados pelos agentes, garantindo compatibilidade com a API e com os modelos definidos.

A equipa definiu também a necessidade de suportar:
- **Dados históricos** (para análise e visualização)
- **Dados em tempo real**
- **Dados futuros simulados** (para testes e previsões)

Foi proposta uma estratégia que permite gerar:
- Um histórico de dados correspondente a **um ano completo**
- Dados contínuos em tempo real
- Simulação de dados futuros em paralelo

**Decisão:**  
Ficou definido que:
- A estrutura dos dados será normalizada e alinhada com os modelos da API  
- Será implementada uma estratégia híbrida de geração de dados, incluindo:
  - **Histórico (1 ano)**
  - **Tempo real**
  - **Dados futuros simulados**
